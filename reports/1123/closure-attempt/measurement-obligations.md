# Independent requirement review — #1123 AC4

## Conclusion
AC4 requires an observed before/after alone-block wall-time pair, not a speed target or a green unit lane. It adds **no blanket requirement to acquire `timed` around every unit-lane reading**. Ordinary commands retain their normal grants; recorded load can make their timings readings rather than comparable budget results. **This does not waive the separate requirement that timed files run under `timed`.** A loaded-budget INCONCLUSIVE is not permission to bypass that requirement.

## Controlling text
- `issue.json`, AC4: “Alone-block wall time before and after is a reading”. Proof: “Unit-lane runs before and after on one commit”. Scope: “the 56 with load or timing gates stay timed; #236's shared sandbox log stream stays alone”. “Runs on: Spark + Mac”.
- `docs/parallel-proof.md` §10: “Speed-ups are readings, before and after on one commit, never criteria, since they depend on the machine's load.” Thus neither beating the historical 557 s nor any percentage improvement, extra repetition count, or clean-exit threshold is AC4's bar.
- §6: “`lanes.mjs` wraps each of its commands by this classification”; `test` holds “The vitest parallel block and `node --test`”, and `build` is “The default for an unlisted command”. `timed` is “Exclusive of every class; waits for load below the core count”.
- §6, Measured runs: “`preflight.mjs` and `perf.mjs` claim timed before their timers start and hold it to the end, so a measured time contains no throttle wait.” This names those runners; it does not say every observational unit-lane reading must use either runner or their outer grant.
- §7 assigns load/timing folders to “The timed list (T9a), run only under a timed grant”. §6 also preserves timed requests made by tests that start measured runners. Those obligations remain even when the enclosing run is only collecting a reading.
- §4 explicitly records Spark builds at “1-minute load 37–58 throughout, so the wall times are readings against each other, never budgets”. §9 says “no tooling change can be measured on top of them”; read alongside §§4/10, this warns against a reliable performance conclusion, not retaining loaded observations. Its hygiene bar belongs to T0, not a new AC4 threshold.
- `docs/technical-design.md`, “The reference Macs”: “Anywhere else the result is a reading, and the budget check is INCONCLUSIVE”. Parallel proof §12a: “A load at or above the cores during a task makes that task INCONCLUSIVE.” Budget rules and their samples/margins are not AC4 requirements; agents “never run or edit the window”.

## Important limitation visible in the supplied base scripts
`scripts/lanes.mjs`, lines 476–492, declares the real unit lane: parallel Vitest, serial Vitest over `alone`, workspace cargo tests, then Node tests. Lines 690–693 classify parallel Vitest/Node as `test`, but serial Vitest/cargo as `build`. `runLanes` itself acquires no enclosing timed grant (lines 933–979).
The base's serial command passes all of `alone`, without subtracting `timed`; the lists overlap. Its own timed-list comment (lines 142–151) and design §7 require timed handling. Therefore **“run the supplied full unit lane under only its build/test grants” is not unconditionally design-conforming**. An enclosing timed grant, as preflight supplies, satisfies this; otherwise mandatory timed work still needs timed admission. A duration observed without it remains an observation, not proof that scheduling requirements were met. This is a base/design discrepancy, not a proposed fix or a reason to silently omit timed files.
Accordingly: normal grants suffice for non-timed work and AC4 does not demand whole-lane isolation; a complete block containing timed work may nevertheless need a timed grant because of its contents. Failure to obtain that grant yields no execution reading for that block, not a substitute wait-time reading.

## Reproducible “one commit” comparison
The design does not prescribe an overlay filename or one unique construction. The faithful comparison holds the workload's commit constant while varying only the issue's mechanism/routing:
1. Pin one common commit **C** and one identical check suite on both sides, including any already-approved/merged blind redrafts. Keep assertions, fixtures, goldens, timeouts, skip policy and result interpretation unchanged.
2. Before = C with pre-T4 implementation/routing; after = C with the precise T4 implementation/routing overlay. Equivalently, when C already contains T4, before = C minus that explicit implementation/routing delta, after = C. Do not revert tests along with a whole issue commit, transplant an unrelated older scripts directory, or change checks to make the comparison run.
3. Preserve the complete unit-lane workload; only the eligible folders' placement and the issue's binary mechanism differ. Record the exact moved paths and each side's actual block membership. The before side's larger alone block and the after side's smaller one are the intended comparison, not a reason to sample either.
4. Record C, exact overlay bytes/digests and application recipe, resulting tree hashes, uncommitted/untracked inputs, commands, relevant environment, tool versions, host/platform, load and build/cache preparation. Parallel proof §4 requires exact-tree recipes and hashes; §10a's tree includes uncommitted and untracked files. Merely sharing HEAD does not establish identical inputs.
5. Each side builds from its own prescribed tree; no foreign shell `DEEP_BIN_DIR`, shared base/change binaries or relocated target. Keep the approved checks identical even if a pre-T4 mechanism check fails. Guarded tooling changes still require their existing approval; a measurement overlay is not an exemption.
6. Keep each before/after pair on the same host/toolchain with preparation disclosed. Report Spark and Mac separately, not one as the other's control. The issue's two-host proof scope remains; disclose any unrun host. Historical “557 s” is context, not the required same-commit before run.

## What “alone-block wall time” measures
The issue names the observable, not a timer API. Use a disclosed, identical boundary convention on both sides: elapsed real time from starting the actual serial-block test process **after its admission waits** to its final exit, including startup, collection, test work and teardown. A monotonic elapsed clock avoids wall-clock adjustments.
Keep request-to-grant/lease-admission waiting separate. It is not execution of the block. Builds or binary preparation outside the block, the parallel block, cargo/Node commands and whole-lane elapsed time are also not the alone-block duration; builds performed inside its tests are included.
Any nested throttle wait after the block starts is genuinely inside that observed wall interval. Disclose it separately when measured; do not silently subtract it or claim a wait-free result without evidence. The wait-free guarantee quoted in §6 belongs to runners holding timed throughout.
The base `runLanes` timer starts before its command loop and ends after all commands, so its `Elapsed`/`PASS unit (... s)` is **whole-lane elapsed including waits**, not AC4's number. Output is buffered until each command returns: timestamps added when that output is printed do not recover the command's true start. Summing individual test times is not block wall time either.

## Failures, completeness and evidence
- A non-zero unit exit does not erase an observed completed block. Assertion failures, including inherited ones, can coexist with a legitimate full-block duration. Report exact exit/signal, failing IDs, skips and completion evidence; do not call the lane PASS or describe failed work as successful throughput.
- Parallel proof §10: “Failures on main stay as they are”; when result-reading changes, before/after FAIL IDs must match. Inherited failures are not permission to edit, waive, mask or retry checks until green. New failures retain their actual states; load does not excuse non-timing failures.
- An unsuccessful earlier/later command does not invalidate a fully observed block if it actually ran to completion. Conversely, build/import failure preventing the block, no grant, runner abort, or a killed/bail-out partial block supplies at most a failed-attempt/partial duration, not the requested complete-block pair.
- Preserve automatic skip outcomes from unchanged checks and identify them as unrun. A completed full invocation with reported skips may have an observed invocation duration; it proves neither those tests nor the time to execute their missing work. Deliberately filtering or skipping files to obtain a shorter reading is not the requested unit-lane proof.
- A missing side, unverified endpoint, truncated block/report or sampled subset cannot stand in for a complete reading. Retain any honest partial observation with its limitation; AC4 remains unproven (`BLOCKED`/`INVALID`/`INCONCLUSIVE` as applicable). Never extrapolate, substitute 0, or manufacture an endpoint. A shortened display is harmless only if retained complete evidence independently establishes the full block and its boundaries.
- Technical design, verdict rules: “every run keeps its output and how it ended, a failed or stopped run included”. AGENTS: “An agent's word is never evidence. Only check results are.” “Nothing missing or unrun passes.”
