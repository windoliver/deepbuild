## What this closure changed in the PR

- **Assets only in `deep-show run`.** The earlier head wrote every registered fixture's assets on every replay of a scenario, which the hub's `deep-show canvas` process does for each call, so a user's evidence store got fixture bytes. Now `run` alone writes them, for listed fixtures only. A planted document keeps its missing asset, and an asset that can't be written is the show's own refusal.
- **The arrangement fixture is scene3d's.** It places `mark.box@1` solids, so it requires scene3d. Listed under motion it was refused with `module_missing` in the r1 set, and `388/shuffle.test.ts` failed. Found by the related run; that file passes now. Motion's file is main's.
- **No new size finding.** On main `deep-canvas-marks/src/modules.rs` and `deep-canvas/src/registry/mod.rs` sit at their size ceilings. The two marks fixtures are built beside their operators in `arrays.rs` and `relations.rs`, and the bare kind table has its own file, `registry/bare.rs`. Both ceilings drop, to 2,040 and 3,711 lines.
- **Merged main four times**, last at `3cf41958f`. The second merge conflicted in `main.rs`, where the `run` command had moved to `answer.rs`; the asset write moved with it. Every other conflict was a snapshot's `set_digest` line, taken from the merged build.
