## What the view does not draw yet

Each of these shows the reason in the layer's place, never part of a frame. The render-back snapshot the agent gets is whole in every case.

- A document that requires a module other than `scene3d` and `motion`: `module_missing: <module>`.
- A 3D document with a 2D item, such as a title or a card's text, which render-back draws over the 3D frame: `module_missing: marks2d`. **This is most figures.**
- The document's own look, a shot's camera pose, an arrangement, a view overlay, a material's maps, an inset's picture, a readout: `feature_absent: <what>`.

Other limits:

- **A frame is asked for when motion's `valid_until` passes.** Water, sway, puffs and flipbooks, which move with no channel, hold still in the app. A still document draws one frame and asks for no more.
- **A change that is still to come redraws the window every refresh** until it arrives, instead of sleeping until then.
- **Each frame compiles the motion program again**, inside `deep-play`'s `evaluate`. #2658 names the same cost for render-back.
- **macOS only.** Elsewhere a 3D layer draws nothing, as before. The non-macOS build was not compiled; the new code is behind `cfg(target_os = "macos")`.
- **Not run:** the app's own 100 ms poll of the hub with a 3D layer (the tests hand the hub's `canvas.drawn` answer to the fixture), a device loss, GPU time and memory, the full preflight, #806's live tests.
