# deep-canvas-physics

## What it is for

The physics canvas module (issue #2009, `physics.world@1`, measured, with backend_bytes state): the world document's reader with the design's defaults, the caps a backend declares and the check that refuses what they rule out, naming the field and the backend, and the backend interface a backend implements. Everything here is this crate's own types, so no backend type crosses the interface. Issue #2010 adds the bake key, the runtime digest and the outputs sampled at the document's frame rate (`src/bake.rs`), and step hashes, the golden comparator and where a golden stands across machines (`src/golden.rs`). Issue #2011 adds roles that expand through a first-party table into collision groups (`src/roles.rs`), the check kind `physics.pairs` over the whole interaction matrix (`src/pairs.rs`), inline `convex`, `mesh` and `compound` shapes, `budget.step_p95`, and sensor entries and exits in the backend interface's `occurrences`. Issue #1918 adds the occurrence list, made canonical and sorted from what a backend reports (`src/occurrence.rs`), the module that fills the core's `column.source@1` with `<world ID>.occurrences` and `<world ID>.<ID>.<read>` (`src/module.rs`), and the reader's kinematic bodies, `follow`, channel motor targets, `breaks_at`, `tag`, `solve` and outputs (`src/doc/reads.rs`). Issue #522 adds a world's declared inputs and `checkpoint.budget` (`src/doc/inputs.rs`), its input track, ordered by (kind, target ID) whoever wrote it (`src/track.rs`), and the byte-budgeted checkpoint ring whose spacing doubles when it would pass its budget (`src/ring.rs`). Issue #523 adds a joint's own state beside its bodies' in the interface and the step hash (a hinge's whole turns and its steps past `breaks_at`), `joint_coordinate` and `joint_force` outputs (`{force, torque}`, its locks' and limits' impulses, never its motor's) sampled into the bake, an output's `crossings`, the `fault` (`speed_cap`, `jam`) and `crossing` rows, gear and pulley joints, and `physics.mass_ratio` (`src/check.rs`). Issue #524 adds `soft@1` ropes, cloth, balloons and soft volumes, each a lattice of particles with stable addresses (`src/doc/soft.rs`, with the world's `capacity`), particles in the canonical state and step hash after the joints, `tear` rows, the backend's read-back of what it built (`held`), and skins: a soft body drawn on an item built on its own lattice, refused at check otherwise (`src/skin.rs`).

## Where new code goes

- A world, shape, body, joint or force field goes in `src/doc.rs`, with its default and range; #1918's fields and the outputs go in `src/doc/reads.rs`; an input kind or field, or a checkpoint field, in `src/doc/inputs.rs`.
- A `soft@1` field, an address pattern or a soft lattice goes in `src/doc/soft.rs`; what a skin checks, bakes and writes into a frame in `src/skin.rs`.
- How a track's entries resolve against the declared inputs, order, fork and join, and the entries a control's entries derive (`from_controls`, which a world's bake, a live play's world and deep-show share), go in `src/track.rs`; the ring's spacing and budget in `src/ring.rs`.
- The occurrence list's kinds, canonical order, bytes and rows go in `src/occurrence.rs`; the manifest and the `column.source@1` entries in `src/module.rs`.
- What a backend can't run goes in `src/caps.rs` as data, and its refusal in `src/check.rs`.
- The backend interface is `src/backend.rs`; a backend lives in its own crate (Rapier's is `crates/deep-physics-rapier`).
- A part of the bake key or how outputs are sampled goes in `src/bake.rs`; a hash, the comparator or a golden's cross-machine verdict in `src/golden.rs`. What the build resolved reaches them as a `Build` the backend's crate passes in. A golden's runtime digest is the seal's, of the set that holds this module alone (`Build::runtime_digest`, #1920).
- A role's groups go in `TABLE` in `src/roles.rs`; a rule a role promises, which physics.pairs holds whatever the table says, goes in `src/pairs.rs`.
- The codes it adds to the check catalog are `CODES` in `src/check.rs`.
- The acceptance tests are in `tests/acceptance/2009`, `2010`, `2011`, `1918`, `1920`, `522` and `524`.

## What it may import

A canvas module crate under `scripts/canvas-lint.mjs`. It reaches the core through `deep-canvas` by crate name and reads JSON with `serde_json`. It depends on no physics engine and does no float math beyond comparisons.

## Deviations

- `src/module.rs`'s manifest names the backend's crate as `physics@1`'s implementation, measured with backend_bytes state, with the pins the build resolved (#1920). The interface has no behavior part until #191, so a build admits only its reference, Rapier. It registers no operator or kind: the host bakes a scene's worlds at check, as the logic module's items are baked. Its conformance-kit stepper and fixture need an engine, so deep-show registers them beside it (#522).
- `src/backend.rs` declares `id`, `caps`, `build`, `step`, `occurrences`, `read`, `canonical`, `held` (#524), `checkpoint` and `restore`; `query`, `move_character` and `drive_vehicle` join it with #1919, #182 and #251.
- `src/doc.rs` refuses by name, with the issue that brings each, the fields no criterion of #2009, #2010, #2011 or #1918 runs: character and vehicle bodies, heightfield shapes and shapes built `from` an item or asset (#927), swing and twist, a drag medium, a spring point or a strength set by input (#2371), the wind, buoyancy, inverse-square, magnetic and Lennard-Jones forces, the input kinds `set`, `activate`, `deactivate` and `blast` and a poke's `address`, `radius` and `falloff` (#2371 too), `jump` (#182), `drive`, `steer` and `brake` (#251), `launch.from` and expressions in an input's `data` (#164), and an output's `reduce`, `average`, `sample`, `keep`, `expr` and `unit` (#2248), and character reads; `src/check.rs` refuses a soft body's `pressure` by the caps, and rack and path joints in kinematic mode, which no criterion of #523 runs.
- `src/bake.rs` keys the scene's channels and drivers a world reads as the values they give at every step (`reads`), and the input track as its entries resolve, defaults merged, so a track written with or without its defaults keys the same bake.
- `src/doc/inputs.rs` reads a grab's `plane` and keeps it, but no `move` here reads it: a move names the point it pulls to.
- `src/occurrence.rs`'s rows carry no time: a host stamps each with its step's time (`timed`) where a scene's readers read it.
- `src/doc/soft.rs` builds a balloon's and a volume's lattice only from the `mesh` a host resolves (deep-physics-rapier's `source.rs`), since this crate builds no mesh; a volume from a mesh asset is refused there (#2457). A soft body's `collision_group` makes it a member of that group, colliding with all; its clusters are named address sets, not engine clusters.
- `src/skin.rs` writes a skin's positions into its item each frame, which scene3d rebuilds on the CPU (a new GPU buffer a frame), not the design's in-place vertex buffer rewrite.
- `src/doc.rs` reads only `step_p95` of `budget`; `memory` and `bake_10s` are accepted and not yet held (benchmarks/physics.mjs measures them for #524's budgets). The hosts block (`host@1`) that will say which hosts have a reference Mac doesn't exist yet, so `scripts/physics-budget.mjs` takes it in its request.
