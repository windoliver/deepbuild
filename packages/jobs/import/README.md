# Import job

## What it is for

The job kind `import` (#162; canvas primitives: Asset job: Lottie import) with its first tool, `lottie-import@1.0.0`, which runs here as WebAssembly: a Lottie file in, a checked document out. Params `{from: lottie, look: generated | <look>@<major> = generated}`; inputs `file` (the Lottie JSON) and `look` (at most one look@1 file; with none, a named look is the shipped look of that name); outputs `document` (canonical JSON, naming its look through `assets/<id>/sha256` and `look: {asset: <id>@1, theme: light}`), `report` (`{issues: [{code, layer, property?, what}], colors: [{color, role, distance}]}`, each issue's `layer` the Lottie layer's `nm`) and `look` (that look@1, kept in the store beside the document that names it). Its output checks, run before any byte is kept: `import.document`, `import.colors_mapped` and `import.no_expression`.

Its second tool, `urdf-import@1.0.0` (#3035; canvas primitives: Asset job: imports), takes `{from: urdf}` and a robot description as `file`, and no `look` input. Its `document` holds one item for each link and one `physics.world@1` with a body for each link and a joint for each joint that has a place, in our units and axes; its `report` is `{rotation, dropped: [{element, name}]}`, the one rotation applied and every element that had no place; its `look` is the shipped clean look the document names. A file that needs a macro expanded, or names a mesh, is refused naming it, and nothing is written. `import.document` also holds each world of a document to the physics module's check. What each element becomes is in `crates/deep-urdf/README.md`.

Its third tool, `table-import@1.0.0` (#3570; canvas primitives: Asset: tables, Asset job: imports), takes `{from: table, member, format: csv | jsonl | xlsx = csv, delimiter: comma | tab | pipe = comma, sheet, header = 1, encoding: utf-8 | latin-1 | windows-1252 = utf-8, columns: {name → {from: header text | index, dtype: i64 | f64 | str, unit, missing, group}}, key, where: [{column, in} | {column, prefix}], max_bytes = 2 GiB}` and the published file as `file`, read as it streams in: the request's base64 is decoded in pieces, and nothing holds the whole file but a workbook. It writes `table` (CSV, header first, its columns in the file's order, a missing cell empty, a number in its shortest form) and `report`, the receipt `{rows_read, rows_kept, columns_kept, missing: {column → cells}, formula_cells, member: {path, sha256, bytes} | null}`. A zip's member is named by its path and inflated as a stream, counted against `max_bytes` as it inflates; an encrypted entry, a member that is or lies inside another archive, a path that leaves the root and a path held twice are refused by name. Delimited text splits by the table probe's quoting rule on all three delimiters, drops a byte order mark, and refuses a byte sequence its encoding doesn't hold, naming the row. A workbook's sheet comes in as the file stores it: a formula is never evaluated, its stored value counted in `formula_cells`, one with none missing; a date cell is an ISO 8601 string. A cell equal to a `missing` marker is missing and counted; any other cell that doesn't parse as its dtype refuses the import, naming the row and the column; `1,234` parses only under `group: ","`. Kept rows stay in the file's order, a key value two of them share is refused, naming it, and a table past 16 MB is refused, naming its size. Its output check `import.table` holds the table to the probe's reading; the hub then writes the table's record with its source, the job and the URL and fetch time of the file it read. The qualification's four table fixtures each plant a defect: the pipe file's withheld `(D)`, the zip whose named member is its second, the workbook whose stored total (250) differs from its cells' sum (260), and the Latin-1 file's é and grouped digits.

## Where new code goes

- `index.ts`: the kind, its output checks and its tools; `deepbuild.json`: the manifest, whose `digest` is the folder's `packageDigest`.
- `tool/`: the Lottie tool's build: `lottie.wasm`, built from `crates/deep-lottie` by `node scripts/lottie-wasm.mjs`, and its Node entry `lottie.mjs`, which the checks also call.
- `urdf/`: the robot description tool's build: `urdf.wasm`, built from `crates/deep-urdf` by `node scripts/urdf-wasm.mjs`, and its Node entry `urdf.mjs`, which `import.document` also calls.
- `table/`: the table tool, plain Node with no build: `table.mjs` (the entry, the streamed request), `zip.mjs`, `text.mjs`, `xlsx.mjs` (the three readers), `cut.mjs` (the columns, rows and receipt) and `probe.mjs`, which `import.table` also calls.
- `fixtures/`: the qualification's files and the bytes each format's tool must write for them, with each look. A fixture runs on the tools whose own params take it.

## What it may import

Nothing outside this folder: it is copied alone at install, and the tool reads only its own folder.

## Deviations

- `look` is declared `many`, since the job API takes no optional input; the tool refuses more than one.
- `tool/lottie.wasm` and `urdf/urdf.wasm` are built files in the tree, as the typeset tool's is, since the plug-in's digest covers every file the tool runs.
- The table tool's file is the job's input `file`, never a `file` field of its params: the job's key holds the input's hash, so the params need not name it twice. A column's index is `index`, beside `from` for a header text, since a field of the params schema holds one type.
- The table fields' defaults are the tool's, not written into the kind's params, so a Lottie or robot import's params and key don't change; a table import that writes a default out has another key than one that leaves it out, and the same bytes.
- A workbook is held whole, under `max_bytes`, since its shared strings may follow its sheet in the archive; a zip's member and delimited text are read as a stream.
- The three planted readers of the qualification are the tool's own, chosen by `DEEP_3570_PLANT`, which only the acceptance tests' planted entry sets: the job API hands a tool only PATH and HOME.
- The robot description tool takes no mesh: a file that names one is refused, naming its path, until the mesh convert-in job (#1984) gives the job one.
