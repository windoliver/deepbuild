not a run.

The suite was not run at the base: there is no #503 code to tell apart, and this machine was asked not to build Rust for
this draft. What follows is read from the base's code. The suite type-checks (tsc -p
tests/acceptance/503-redraft-ac4/tsconfig.json: clean) and collects one test (vitest list --root
tests/acceptance/503-redraft-ac4). Its fixtures, FFmpeg's reference decodes and its judge were run once by hand with the
local FFmpeg 9.0.2 (README: Authoring check).

What the base has: `deep-show run` with #498's `media_decode` and `workers` calls and the planted `decodes_in_app`.
Its decode worker reads WAV, PNG, MP4/QuickTime and playlists only (`format()` in crates/deep-codecs/src/lib.rs); any
other file is refused `unreadable` ("not a format the worker reads"). An AAC track in MP4 goes to the platform's AAC
decoder (`apple::decode_aac`). The scenario's `planted` doesn't know `lossy_one_sample_late`, `lossy_level_off` or
`vorbis_missing` (an unknown name answers bad_input).

answers ok, and the first check fails, listing at least these eight sentences:
