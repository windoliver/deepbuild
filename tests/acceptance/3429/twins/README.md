# Twins for the 3429 tests

No implementation existed when these tests were drafted, so no twin folder is here yet. Each twin is the merged
implementation with exactly one rule broken as below, and nothing else changed. A twin replaces product files only,
never a file under `tests/`, and is kept as its wrong lines: `twins/<name>/lines.json`, each key the repo path of the
file it edits (`tests/acceptance/1832/README.md`, The line form). #55's plugin reads its planted wrong program in
`packages/paseo/server/plant.ts` alone (`DEEP_PASEO_PLANT`) and the hub in `packages/hub/src/plant.ts`
(`DEEP_HUB_PLANT`), so a plugin or hub twin may be that file's line with the plant's name fixed, once the implementer
adds the plant; a facts or corpus twin edits `adapters/paseo.facts.json` or the recorded set.

Every twin but the first is laid over a change whose corpus holds the recorded run (`../README.md`, The recorded
run): without the run the tests of criteria 2 to 6 read BLOCKED once their own assertions hold, and BLOCKED proves
nothing.
