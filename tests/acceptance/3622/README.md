# Acceptance tests for #3622: the carried GPUI patches on vendored gpui-fast 0.1.19

These tests cover #3622's four criteria: the three vendored `gpui-fast` trees pinned at 0.1.19 and listed in the carried-patch table, `node scripts/vendor-rebase.mjs check` passing against the pristine releases and failing on each planted fault, the `objc2-metal` port, and the rows retired for 0.1.19.

They were written blind from issue #3622 (its Scope, the four criteria and Proof), the issues it links (#3618, #1433, #1426, #3502, #241), its follow-ups #3623-#3631, `node scripts/design-section.mjs --issue 3622` (the Decided row "The app's toolkit", with #3618's fast-backend paragraph, and canvas-primitives' GPU surface) and the base commit `4471593f`, where nothing of #3622 exists. From the base I read `AGENTS.md`, `scripts/vendor-rebase.mjs`, `vendor/gpui-pre-apple/upstream/README.md`, `vendor/`, the root `Cargo.toml`, `.cargo/config.toml`, `scripts/lease`, `scripts/throttle.mjs`, `scripts/proof-change.mjs` (`criterionId`) and `tests/acceptance/1426/` (its README's surface). I unpacked the three pristine 0.1.19 releases from static.crates.io. No implementation of #3622 was read. Per AGENTS.md the implementing agent doesn't edit these files; a dispute goes to a blind redraft of this job.

## The surface (my choice where the issue names none)

#1426's surface stands: the table under `## Carried patches` in `vendor/gpui-pre-apple/upstream/README.md` with its columns `Behavior | Issue | Files | Test | Budget | Removal`, Files as backticked repo paths, Test as `` `<path> › <name>` ``, Budget `—` or `N over: reason`, the mark `DeepBuild patch (windoliver/deepbuild#n)` within one unchanged line of its hunk, the budgets of 8 lines a hunk and 40 added a file, and `check`'s `FAIL` lines. The judges read every Markdown table in that README by its header's names, so rows for the new trees may sit in that table or a table of their own.

- **Pinned.** `vendor/<crate>/Cargo.toml`'s `[package]` has `name = "<crate>"` and `version = "0.1.19"`, for `gpui-fast`, `gpui-fast-apple` and `gpui-fast-macos`. The workspace's own pins (`Cargo.toml`, `.cargo/config.toml`) are #3630's, so they aren't read.
- **The pristine release** is the `.crate` from `https://static.crates.io/crates/<crate>/<crate>-0.1.19.crate`, unpacked into the test's own temporary folder each run. A changed file is one whose bytes differ from the release's, or one the release lacks; a vendored `LICENSE*` the release lacks isn't one; a file only the release holds isn't one; `target/` and `upstream/` aren't read.
- **A planted copy** holds `scripts/`, the three trees, the README, `package.json` and each test file a row names, committed in a scratch git repository with git's own variables stripped. `check` runs there with `DEEP_VENDOR_RELEASES` naming the folder of fresh releases. The copy holds no other vendored tree, so its unplanted run fails too (rows of other trees have no hunks there, row tests can't be listed without `node_modules`): every plant is judged by what it adds over that control run.
- **Naming file and line.** A `FAIL` line holding `<path>:<line>`, or the path and `line <line>`, with `<line>` the planted line's number in the vendored file. This holds for the changed file with no row too: the base's `FAIL <path>: no row in the carried-patch table` names no line, so the base's `check` fails that plant even with the trees in place.
- **A row retired for 0.1.19** is a body row of a Markdown table under a heading whose text holds `retired` and `0.1.19`, for example `## Retired for 0.1.19`. It names its issue (`#n`) and the upstream change: an `owner/repo#n` other than windoliver/deepbuild, a GitHub pull or commit URL, or a commit hash. A row of the carried table that stays on gpui-pre and simply lists no gpui-fast file isn't read as retired.
- **The objc2-metal compile.** `cargo check --lib --message-format=json` in a scratch copy of `vendor/gpui-fast-apple` beside `vendor/gpui-fast`, with `patch.crates-io.gpui-fast` pointed at the copy, run through `scripts/lease`, with `CARGO_INCREMENTAL=0`, `CARGO_PROFILE_DEV_DEBUG=0` and its own target folder. With no Metal compiler (`xcrun --find metal` fails, as with Command Line Tools only) it adds `--features runtime_shaders`, which leaves the shaders to run time and still compiles every Rust file.

## How to run

From the repo root, on Node 24:

```sh
node --test tests/acceptance/3622/ac1-pinned.test.mjs       # AC1; network; node_modules for check's vitest lists
node --test tests/acceptance/3622/ac2-plants.test.mjs       # AC2; network
node --test tests/acceptance/3622/ac3-objc2-metal.test.mjs  # AC3; network, cargo, a build grant; minutes when cold
node --test tests/acceptance/3622/ac4-retired.test.mjs      # AC4; network
node --test tests/acceptance/3622/wrong.test.mjs            # the judges against wrong programs; passes at the base
```

Every copy and build goes under the system's temporary folder and is removed when its process exits. Nothing writes to the repo. AC1's run of `check` is the script's own, on the real tree, so it may fill `~/.cache/deepbuild/vendor-releases` as the script does.

## Assumptions a redraft may revisit

- **"That row's check" is `check`'s verdict on the row's file**, not the row's own test: the issue leaves running the carried-row suite to #3631, and no workspace crate builds on `gpui-fast` until #3630, so a row's test can't see the vendored trees. The removal is the row's line taken out of the table, the act of retiring it, with its change left in place. A row whose file another row of the same issue also lists is passed over, since that row would still own the hunks.
- **Coverage is by issue, not by row.** #140, #390, #391, #1482, #1551, #377, #1434 and #499 have several rows; one row of the issue on a gpui-fast file, or one retired row naming it, covers it. The Scope's two exceptions (#1550's line break, #1482's retained accessibility) aren't hard-coded: a README line naming the issue with its follow-up covers it.
- **The carried files that must compile** are the changed files of `vendor/gpui-fast-apple`. Errors in unchanged `src/fast/` files are left to #3625 ("updating gpui-fast's own `src/fast/` match sites" is out of this task), and only default features plus `runtime_shaders` when needed are built, since #3625 owns `test-support`. The eight renderer files #3502 counts aren't required by name: a file of them retired with its row needn't be there.
- **The 9-line plant** is marked with the row's issue, so only the budget is wrong; a row that raises its budget is passed over, since its number may absorb one breach.
- **Network.** Each test that compares with a release fetches the three releases; the compile also fetches crates. Without them a test fails with INCONCLUSIVE, never passes.
