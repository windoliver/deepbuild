How the #506 acceptance suite fails at the base, ef869ad87 (main).

Not run against a binary. The surfaces these tests drive plainly don't exist at the base, so no GPU build was made
just to watch them fail; each line below is read from the base's code. The type check passes:

  $ npx tsc -p tests/acceptance/506/tsconfig.json
  (no output, exit 0)

What the base has and lacks, read from its code:

- No inset kind. `inset@1` is registered by no canvas module (crates/deep-canvas-scene3d/src/spec.rs has none;
  `display@1`'s `screen` param only names an inset ID). The document check keeps an item of an unknown kind and skips
  it with the notice `unknown_kind` (crates/deep-canvas/src/document/check.rs, "the item is skipped"), so a scene draws
  as if the inset weren't there.
- No item-level `anchors`: `anchors` isn't in ITEM_KEYS (crates/deep-canvas/src/document/mod.rs), so a document whose
  item carries it is refused by the check.
- No `overlay.view@1`: skipped as an unknown kind.
- `overlay.frame@1` is placed at its anchor's projection (crates/deep-canvas-scene3d/src/scene.rs, `overlay`), but
  `view3d` paints it only into a window (crates/deep-gpu-layer/src/view3d.rs: `p.overlays.insert` under `args.window`),
  never into the final target, and its frame draws only `circle@1` and `rect@1` children; `view3d` has no `overlays`
  reply field.
- No `camera.framing`: registered by no module at the base (#1938 is open), so a requirement naming it is BLOCKED
  `module_missing`.
- The scope's Return acts only on a focused pick target (crates/deep-canvas/src/scope.rs: `done.pick =
  self.focused_target(doc)`); a control's own Tab stop takes no Enter.
- `deep-gpu run --planted <name>` with a name `Planted::parse` doesn't know prints {"ok": false, "code": "bad_input"}
  and exits 2 (crates/deep-gpu-layer/src/main.rs: `bad_input`).
