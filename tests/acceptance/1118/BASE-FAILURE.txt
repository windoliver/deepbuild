## A planted implementation, and the planted wrong programs

No implementation exists yet. To check that the tests can pass and that each named wrong program fails them, a
throwaway planted implementation (written for this check only, kept out of the repository) was put in a scratch copy
of this checkout's scripts/: bays.mjs gained a proof-wide pair claim (refusal() and acquire('bay-pair') as T1 has
them) and a per-use replace (T1's byte-compare replace into <pair>/base or <pair>/change from the use's exact file
list, recreateGit, T1's lock-keyed install, then one line `BAY use {index, role, bay, use, tree, overlay,
untracked, crates, installed, written, deleted}`); baseCheckout, changeCopy, the twins, crash and replay called it in
place of their temporary copies; proof.mjs printed `reading proof: wall time <s> s` at its end. On the Spark (20
cores, Linux arm64, node 24.22.0, npm 11.19.1):

  ℹ tests 8, pass 8, fail 0, in 15-26 s (each proof about 3 s; the lock tests 7-8 s, the Rust test 7 s, the shared
  pair of runs 6.5 s).

Then one rule at a time was broken in that planted program (PLANTED_TWIN=<name>), and the suite run again:

- keeps-overlay (the replace before a use never deletes a file the use's recipe lacks):
  ✖ #1118.dc689388 … AssertionError: in run-1, the replay-base use's copy is not exactly its recipe when replay runs
      + 'tests/acceptance/9118/a.test.mjs: not in the recipe', … 'tests/helpers/change-only.mjs: not in the recipe'
  every other test passed.
- lock-blind-install (npm ci before every use, whatever the lock):
  ✖ all three #1118.5a7b1fc3 tests … AssertionError: npm ci ran 6 times …, not 0 / not once
  every other test passed.
