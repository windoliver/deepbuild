## Kept from the first draft

The declared surface: `docs/spikes/2649/record.json` (`main`, `counter.command`, `subjects[...]` `{log, sha256, totalStarts}`, `rows[]` `{subject, caller, program, count, instructions, unread}`), the raw counter logs it cites (relative, pinned by sha256), `<root>` as the caller of the measured command, `README.md` as the human table. Row `use`, `verdict`, `heldBy`, `replacement` and `change` are no longer read by this test: the criterion says nothing of them (they are AC2's). The first draft's AC2 filters `tableProblems`, which is unchanged in `../validate.mjs`; if AC2 is redrafted too it must stop leaning on it.

## What changed, and why (the counter's semantics)

1. **Pid reuse.** The first draft keyed the counter's `reap`, `exit` and parent paths by pid in a `Map`. The idle subject is an hour at up to 20 starts a second, so pids wrap and are reused; a later reap of a reused pid overwrote an earlier one's, so two starts of one helper were both given the later count (a synthetic log with reuse: first draft sums 80, the redraft 70). The redraft reads the log in order and gives each end line to the latest start of that pid that has no end yet, and resolves a start's caller from the parent's start at that point in the log.
2. **Which end counts.** Per `benchmark.mjs`: a `reap` line (the reaper's read) first; a child whose count was denied (`unread` line) has none even if it also wrote its own `exit` line; an `exit` line only for a child nothing waited for; no end line at all (still running) is also a start with no count. Both kinds go in the row's `unread`, never as 0 instructions.
3. **Root.** The first draft called any parent absent from the `start` lines `<root>`. The runner logs no `start` for the measured command, only a `reap` of it. The redraft takes as `<root>` only a parent the runner reaped without a start; any other unknown parent is a problem (the start can't be given a caller), not silently `<root>`.
4. **"Every" start.** The log says when starts are missing: a process's children's elapsed time is the sum of what it reaped, to the tick, and a mismatch means a child went unlogged (a platform binary such as `/bin/sh` the library can't enter; `benchmark.mjs` calls this `uncounted` and withholds the count). The redraft applies the same accounting (observers `/bin/ps`, `/usr/sbin/lsof`, `/usr/bin/log` exempted exactly as `benchmark.mjs` does) and fails when it shows unlogged starts, or a start with no end line, since a table of the logged starts would then not list every start (invariant 2). The first draft only compared the table to the lines present.
5. **A line the counter writes.** Each line must be a `start`, `reap`, `unread` or `exit` with the field count and integers `count-children.c` writes; others are problems, so a hand-edited or truncated log fails.
6. **"Hour-long".** The first draft read `subjects["idle-hour"].durationSeconds` from the record, the spike's own word, and the log has no wall-clock. The runner's `reap` of the measured command does carry its elapsed time in mach ticks. The redraft asks for `counter.timebase` `{numer, denom}` (1/1 or 125/3, the hosts the lane runs on) and requires some root's reap elapsed to be at least 3600 s at that timebase. `durationSeconds` is dropped. This is the one added field; the log alone can't show the hour, and a record field can't be checked against anything else. If the idle run's measured command is not run under the lane's runner the check fails: that is the criterion's "from the perf lane's child counter".
7. **"A table ... with its count and its instructions".** The first draft only checked that README names each program and caller anywhere. The redraft requires a markdown table row (a line starting `|`) in `README.md` whose cells include the row's program, caller, count and instructions retired (backticks, backslashes, `&lt;`/`&gt;` and thousands separators `, _ '` are ignored). Instructions are as plain integers; if it prefers "1.2M" the test will fail it: the issue leaves the format open, the integer is what the record holds.

## Not asserted

Which commit is main, that the idle run was idle or the command check sandboxed, any number of starts, any threshold: the issue gives none, and no kept file can show them. Also unhandled: an end line written before its own start line (a threaded parent logging late); it would read as a root and, if the pid is later reused, fail the accounting, which is the safe side.
