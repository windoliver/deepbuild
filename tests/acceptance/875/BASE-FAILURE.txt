from a run where it reached its judgement, and the run is named. The judgement code is the same in all three runs; the
08:42 run predates two diagnostics-only changes (the 180 s lock wait, up from 60 s, and the "held" field in messages).

Expected failure per test:

  merge base, and the base hub took that non-zero exit as proof: no INVALID verdict; the claim reads "says done 1/1".
  This is the issue's bug ("any non-zero base exit counts as proof").
- AC3: the claim reads PASS (says done 1/1), but the base run records tests_run 0 (the base hub records 0 for every run,
  and its base checkout had no own files, so the test file wasn't there): the AC3 judgement fails at "on the merge base
  the check's test must run".

  start), never a pass. The base hub itself is the wrong program AC4 names, and AC1 and AC2 fail on it above.
