Result: 13 of 13 tests fail; none passes at the base.

Why each fails. The base refuses the piece itself, with one error: `bad_path` at `channels/count/target`
("`data/count`: a path names at least one field below the ID"), where the design's path grammar says "A channel may
key `data/<name>`". It also skips 12 of the piece's items with `unknown_kind` notices (text@1, rect@1, frame@1, star@1,
marks@1, scale@1, vector@1 and sky@1 are not in the kind registry of the full build). So every test that needs the
piece presented stops there, on a missing surface:

- AC1 (present.test.ts), first test: "AC1: the piece is presented": `refused`, the error above.
- AC1, second test (the build without data): "the rest of the piece is presented, not refused whole": `refused`, with
  the error above and `module_missing` at `requires/modules/data` for the whole document.
- AC2 (renderback.test.ts), both tests: "the piece at 0s is presented" / "the piece is presented": `refused`. The
  planted `seeds_noise_from_clock` (which exists) is not reached.
- AC3 (query.test.ts): the summary test, "the piece is presented": `refused`; the sampled-times test: deep_query
  answers `no_revision` (no revision of the piece was ever presented), so `values` is missing; the glyph-run test:
  `read` answers `ref_unresolved` for the same reason. The new planted `relation_from_previous_box` is not reached
  (the base would answer it `bad_input`).
- AC4 (status.test.ts), all three tests: "the piece is presented" / "the bound piece is presented": `refused`.
  `deep-gpu`'s `status_before_tone_map` (which exists) is not reached.
- AC5 (app.test.ts): the Driver's first step (scope before the first click) finds the piece `refused`.
- AC6 (ask.test.ts): deep_query of the formula's bounds at 1.5 s answers `no_revision`.
- AC7 (shown.test.ts): no check run has written $TMPDIR/deep-1162-proof/ac7/chart-formula.png; it fails (missing
  files fail; only a missing or stale taste call is INCONCLUSIVE).

What lies behind the first refusal, found by two debug runs with piece.json changed by hand and then restored
(regenerated from the same generator; no expectation was changed by them): with the channel's target written
`data/count/value` the base still refuses it ("motion.compile can't evaluate this"); with the `count` channel removed
it refused a star@1 placed straight in the row (`no_box`), which is why the badge sits in a fixed 64 × 64 frame, #375's
form for a row child (this changed the fixture before this run); with that, it refuses the mark sets' table columns
(`asset_missing` at `items/bars/params/columns/key/from`): the hub's deep show doesn't read an imported table yet.
