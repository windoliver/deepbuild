# #570 acceptance tests: the run on the base

Base d2623d97 (no lifecycle table, no scripts/lifecycle.mjs, no lifecycleGaps/machines/LIFECYCLE_OBJECTS export,
no task.withdrawn or move.refused kind; the record's asks projection writes an event's status whatever the row held).
Node 24.22.0, Linux arm64, `npm ci` in the checkout. Paths redacted: the checkout reads <checkout>, temp folders <tmp>.

All 29 tests fail at an assertion; none fails to load. Where they fail:
- 26 tests stop at their first assertion that the real table they read exists (packages/contracts/schemas/<object>.machine@1.json),
  or that @deepbuild/contracts exports lifecycleGaps (2 tests).
- moves.test.ts "a planted handler that moves a defaulted ask to answered is refused": the base is the hub that sets
  state directly. The core's ask.answered after its ask.defaulted is accepted, and the ask ends "answered"
  (Expected "defaulted", Received "answered"), with no move.refused in the log.
- withdrawn.test.ts "your withdrawal from your card (app)" and "(cli)": task.withdrawn is no catalogued kind, so the
  record refuses it at its schema ("no event kind task.withdrawn is catalogued ...") and the task never reaches withdrawn.

The planted wrong programs (README, Wrong programs) are planted in the tests themselves, except AC6's checker that
reads only final states, twins/final-states-only. Checked by hand on a scratch copy holding the twin and a sample
ask.machine@1 (created, then defaulted, then answered): it prints
  PASS lifecycle replay: <tmp>/log.jsonl: 1 moves
and exits 0, so replay.test.ts's planted-log test (which requires exit 1 and a FAIL line naming ask.machine@1) fails on it.
