# 0006: The panel import check

Status: accepted. Moved from comments in `crates/deep-app/src/panel_module.rs` by #1847 ([0001](0001-code-carries-no-comments.md)). #1425 states the rule these serve: a panel imports `@deepbuild/panel` and its own scripts only, refused at pack check and at load. The decisions below are the ones written nowhere else. Each refusal comes from one rule: what the check can't read for certain is refused, since a name it can't read could be the toolkit's.

## The files the check reads

- **A panel's every file is read, or the panel is refused.** `scripts`. More scripts or folders than `MAX_SCRIPTS`, a folder or entry the walk can't list, an entry that is neither a file nor a folder, and a name past ASCII each refuse the panel rather than leave a script unread the runtime could still open. A pipe named `*.js` would hang the read. A file system that folds case may match a name past ASCII to a script's. The cap stops a package from making the check walk forever.
- **The served module is skipped wherever it came from.** `scripts`, `SERVED`. `serve` rewrites `@deepbuild/panel.js` before gpui-shell reads it, so a copy an earlier build or the panel left there neither refuses the panel nor runs. Reading it refused panels whose folder held a copy from another build, as the `codex` and `claude-code` folders do once loaded from another build (#1847's final review).
- **The served module is never written through a link.** `serve`. A link at the `@deepbuild` folder is removed, and the module is written to a temporary file in that folder and renamed over `panel.js`, so a symbolic or hard link there is replaced rather than written through. A panel can't make DeepBuild overwrite a file outside its folder, and gpui-shell reads the file `serve` wrote (#1847's final review).
- **Nothing may sit where the module's own name resolves.** `scripts`, `MODULE`. gpui-shell resolves `@deepbuild/panel` to a file of that very name, in any case, before the served `panel.js`, so a panel may bring nothing there. Its `.d.ts` typings beside them are no module and may stay.
- **One test picks the files read and the files a panel may import.** `script`. A name is a script's when it ends in `.js` or `.mjs`, in any case, since a file system may not tell them apart. A file a panel imports is then always one the check read, `.js` alone included.
- **A panel's own import names a plain-character script.** `check`. Anything but `@deepbuild/panel` names a file under the panel's root, bare (`evil.txt`) or not, and must be a `.js` or `.mjs` script named in letters, digits, `.`, `_`, `-` and `/`. The loader reads some other names its own way: gpui-shell cuts a name at its first `?v=`, so `./a?v=1.js` loads `./a`.

## Reading a script as JavaScript's lexer does

- **Lines are the lexer's lines.** `imports`, `scan`. `\n`, `\r\n` once, a bare `\r`, U+2028 and U+2029 each end a line, so a refusal names the line the runtime reads.
- **A module name is one plain string.** `imports`. An escape spells the name some other way than its text (`"gpui\x2dkit"` is the toolkit's), and a control character may end it early where the runtime reads it. A template literal as a statement's module name, and an `import(…)` or `require(…)` of anything but one plain string, are refused. A tagged `` require`…` `` is a call, whatever parentheses come later on its line.
- **A method named `import` or `require` is no call.** `method`. The name must stand where only a method's can (after `{`, `}`, `;`, `,`, `*`, `static`, `get`, `set` or `async`), and its `)` be followed by `{` on the same line with only white space between in the source. A template's blanked text is no white space, so ``import(m)`${{}}` `` is a call. A call there followed by `{` doesn't parse; one elsewhere may (`class A extends import(n) {}`), so it stays a call.
- **Each call's parentheses are matched once.** `imports`. The matching `)` of every `(` is found in one pass, since scanning to the file's end for each call let 50,000 unclosed `import(` take 54 s (#1847's final review).
- **A `/` read either way is refused unless both readings see the same code.** `scan`, `Before`. After `}`, or after `of`, `yield` or `await`, which are keywords only sometimes, a `/` may divide or start a regex. So may a `/` after a line terminator that follows a value, since a statement that can't go on (`let a`, `debugger`, an import with no `;`) ends there. The two readings agree only when the would-be regex holds no literal, bracket, `*`, import or slash of its own (`[/*]` opens an array and a comment as division) and no slash follows it. Read as division, the text between the slashes must also end in a value, or the closing `/` starts a regex there (`a / / */`, `a / x in /`).
- **A regex follows the head of a statement that takes a condition.** `scan`. After the `(…)` of `if`, `for`, `for await`, `while` or `with`, a `/` starts a regex.
- **`++` binds by its line.** `scan`. After a value on its line it is postfix (`a++ / b` divides); otherwise it is prefix (`++/re/.lastIndex`), since a line terminator before `++` ends the statement. After `of`, which may be a name or a keyword, `of++` and `of ++x` both read either way.
- **A number holds one `.`.** `scan`. A number's own `.` (`1.5`) follows decimal digits only. A second (`1.5.x`, `1..x`, `1e5.x`, `0x1.x`) reaches a property. A name after a number's own `.` is no property (`1. in /re/`), as only a `.` of its own reaches one. A property's name is no keyword and no call: `this.import("en")` imports nothing.
- **What the check doesn't read is refused.** `scan`, `space`. A character past ASCII, a `\` or a control character outside a literal or a comment is refused rather than read, so white space is the four ASCII kinds only. A string no quote closes is no script QuickJS runs, so the scan stops there. A `\` before a line terminator continues a string past it, `\r\n` whole. A byte-order mark is no code.
