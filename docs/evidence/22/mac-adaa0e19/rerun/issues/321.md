Calls that need authority are held at PreToolUse with an ask, by the guard engine's effect and tool classes, whatever a sorter answered or a server claims.

**Epic:** #2 · **Part of:** #22 · **Design:** [An ask, and your answer getting back](https://github.com/windoliver/deepbuild/blob/main/docs/technical-design.md#an-ask-and-your-answer-getting-back) · [Decided](https://github.com/windoliver/deepbuild/blob/main/docs/technical-design.md#decided)

### Scope
- A "proceed" never covers a call that needs authority: in the turn a "proceed" starts, a call whose effect class, by the guard engine's classes (#304), is push, merge, dispatch, send or delete, or that would spend, is held at PreToolUse with an authority ask naming it, whatever sorter answered; the core classifies the call, never the question's words; #84 keeps the sorting
- MCP tools on the guard path, for every server a session loads, synced or not: each server's tool list is recorded at each session start (#18) and at install and update with every tool's input schema digest and hints; a new or changed tool that can change or destroy is held at PreToolUse with one ask per server update, its hints shown as the server's own claims, tools counted as read pass, and a saved decision about a tool lapses when its schema changes

### Acceptance criteria
- [ ] A planted sorter answers "want me to push to main?" with "proceed": the proceed is recorded with its rule, and in the turn it starts the agent's `git push origin main` is held at PreToolUse with an authority ask naming the push, which waits for your answer; after the same sorter's "proceed" for "want me to run the tests?", `npm test` runs with no ask. A core that lets a "proceed" cover the calls of the turn it starts lets the push through and fails this test, naming the call
- [ ] A server update that adds `delete_repo` holds that tool at PreToolUse until you approve it once, and the server's read-only tools keep working
- [ ] A server update adds `post_update` with `readOnlyHint: true` and no facts entry: it counts as change, so its first call is held at PreToolUse with the update's one ask, and the fake server receives no request until you answer; a classifier that trusts the hint lets the call run, and this test fails on the fake server's request count
- [ ] A server you added to Claude Code yourself, never synced by DeepBuild, whose tool list at the next session start adds `delete_repo`, has that tool held at PreToolUse the same way; a guard that holds only synced servers' tools lets the call run and fails this test, naming the server
- [ ] On the virtual clock, the held push, the held merge, and the new `delete_repo` and `post_update` tools each take no at the 1-day authority deadline, and the call never runs; a hold filed as a choice whose recommended option approves fails this test, naming the source

### Proof
A planted sorter's proceed meeting a held push, and fake servers whose new tools are held until you approve, each shown failing first.
