What an ask is and how an answer counts: its kinds, what it is pinned to, superseded and moot, and the trusted path that sets decision. This is the part of asks the verdict spine needs.

**Epic:** #2 · **Part of:** #22 · **Design:** [An ask, and your answer getting back](https://github.com/windoliver/deepbuild/blob/main/docs/technical-design.md#an-ask-and-your-answer-getting-back) · [Plans before acting](https://github.com/windoliver/deepbuild/blob/main/docs/technical-design.md#plans-before-acting) · [Decided](https://github.com/windoliver/deepbuild/blob/main/docs/technical-design.md#decided) · [Question card](https://github.com/windoliver/deepbuild/blob/main/docs/canvas-primitives.md#question-card)

### Scope
- Ask kinds: authority, unblock, taste, exception and a real choice between options, plus the early question about what done means. A taste call or a choice can be provisional: work goes on with the recommended option, marked as undoable, and only steps that leave the machine wait for your answer
- Every authority ask shows its plan: the steps, what each changes, the undo and the cost
- Each ask is pinned to what it shows (a commit, a document revision or an evidence hash); an answer given after that moved shows what changed and is recorded as answered on that revision, and a provisional choice is offered again only when the change touches what it decided
- Two more outcomes: superseded, when a newer ask from the same session on the same subject replaces it, and moot, when its check passed or its attempt was replaced; neither counts in Needs you
- Each option of an authority ask, including one raised by an agent's permission request, declares `decision`: `allow`, `deny` or `none`. Only DeepBuild writes an `allow` option (on an authority ask it approves the plan the ask shows), and options an agent writes declare `deny` or `none`. The trusted path sets the answer's `decision` from the option you chose, kept apart from the option's ID and your words, and words alone are `none`

### Fields
**[Ask](https://github.com/windoliver/deepbuild/blob/main/docs/technical-design.md#ask)**
- `{kind: authority | unblock | taste | exception | choice | definition, question, options, recommended, deadline, fallback, default, provisional, owner, pinned_to}`. With a provisional ask, work goes on with the recommended option, and only steps that leave the machine wait. Each option of an authority ask, including one raised by an agent's permission request, declares `decision`: `allow`, `deny` or `none`. Only DeepBuild writes an `allow` option: on an authority ask it approves the plan the ask shows, and options an agent writes declare `deny` or `none`. The trusted path sets the answer's `decision` from the option you chose, kept apart from the option's ID and your words, and words alone are `none`.
- It can never: Reach you when a rule answers it or the agent could take the step itself, or lack a deadline, a fallback and a default

### Acceptance criteria
- [ ] An item that isn't one of the ask kinds can't be created as an ask
- [ ] A provisional taste call lets the agent carry on with the recommended option at once, and your later answer undoes it if you choose differently
- [ ] A step that leaves the machine (a push, a post, a payment) still waits for your answer, even under a provisional ask
- [ ] An answer given after the commit an ask showed has moved shows the diff since then and is recorded as answered on the old commit, and a provisional choice whose files the change didn't touch isn't asked again
- [ ] A second ask from the same session on the same subject closes the first as superseded, an ask whose check passes closes as moot, and neither stays in the count
- [ ] An ask that doesn't state what it decides, its options, the recommendation and the default fails its schema
- [ ] Text typed in the session closes a question that needs no authority, as the answer to that question only, recorded as answered in the session and unverified and never saved as a decision; an authority ask stays open, its card shows on the trusted path with the typed words beside it, and one tap answers it; an ask whose action already ran is never defaulted to no afterwards
- [ ] After your approval only the plan whose digest you were shown runs, bound to your click's token; a changed plan needs a new approval, and an agent passing a flag never counts as one
- [ ] An authority ask with an option that has no `decision`, or any value but `allow`, `deny` or `none`, fails its schema, and a `deep_ask` whose own option declares `allow` is refused naming that option
- [ ] An answer that arrives carrying its own `decision` is refused naming the field. Answering a push's authority ask with only the words "yes but not on main" records `decision: none`, and the push never runs; choosing its `allow` option records `allow` and runs only the plan whose digest it showed. An answer path that infers allow from "yes" in your words, or copies `decision` from the request, fails this test
- [ ] Every `ask.created` carries its `fallback`, `owner`, `key` and `pinned_to`, and one without any of them fails its schema, naming the field; dropping the asks table and replaying the log rebuilds each ask with all four, so a rebuilt ask past its deadline still goes to its fallback. A catalogue whose `ask.created` leaves `fallback` to the live table rebuilds an ask with none and fails this test, naming the ask
- [ ] An ask raised before `/compact` and a newer ask on the same subject raised after it, under the rotated ID of the same thread, close the first as superseded and show one card; five asks open across a `/clear` fold a sixth into the exception; a hub that keys either rule on session ID shows two cards or no fold and fails this test, naming the thread
- [ ] An authority ask that took its default no at 12:00, then gets an allow from `deep inbox answer` at 12:01, records that answer refused, naming defaulted and 12:00; nothing reaches the agent, and the card offers the undo; a hub that records the late allow as answered delivers a second answer and fails this test, naming the ask
- [ ] Every place that raises an ask has one row in `ask.sources@1` naming its kind, and a planted source with no row can't raise one, naming the source; each row's fixture lets the deadline pass on the virtual clock and checks the default, so a budget raise and a paid generation each take no at their deadline as authority asks, and a table that files the paid generation as a choice with an approving default fails this test, naming the row

### Proof
Schema refusals for each missing field, the push answered in words recording decision none, and asks rebuilt from the log, each shown failing first.

### Added Oct 9
- An ask leaves Needs you only on your answer, a rule you set, or its deadline; Later hides it until a time before the deadline. Looking at it never answers it.
- A BLOCKED or INCONCLUSIVE claim becomes a question that names the evidence that would close it. Its ID is a hash of its normalized text and scope, so the same question asked twice is one record, and each change cites the revision it replaces. No agent can withdraw it or mark it out of scope.
- An approval binds to the digest of the exact plan you were shown and to your click's token, and only that plan runs.

**Done when:** a repeated question merges into one record, and no agent-reachable path can close one.
